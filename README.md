# Campus Food Link

TanStack Start, React, TypeScript, Tailwind CSS, and shadcn/ui starter organized with [Feature-Sliced Design](https://fsd.how/).

## Structure

```text
src/
  app/
    styles/             # Global styles and design tokens
  pages/
    home/
      ui/home-page.tsx   # Home page implementation
      index.ts           # Public API of the home slice
  shared/
    assets/              # Reusable static assets
    lib/                 # Reusable, business-agnostic code
    ui/                  # Reusable UI primitives
  routes/                # TanStack Start file routes; thin page adapters
  router.tsx             # TanStack Start router entry point
  routeTree.gen.ts       # Generated by TanStack Router; do not edit
```

`app` holds application-wide setup, `pages` holds screens, and `shared` holds code without page-specific business logic. The framework's route files and router entry point remain at their TanStack Start paths. Route files should import a page through its slice's `index.ts` and keep route-specific setup there.

Add `entities/<business-name>` when a business concept needs reusable model or UI code. Add `features/<action-name>` when a user action is reused across pages. Each new slice should expose only what other layers need through an `index.ts`; keep its implementation in purpose-based segments such as `ui`, `model`, and `api`. A slice may import from lower layers, but not from another slice in the same layer. Avoid empty layers and placeholder slices until they have a real use.

Use kebab-case for new file names, for example `food-list.tsx` and `fetch-food-items.ts`. Keep filenames required by TanStack Router (`__root.tsx`, `index.tsx`) and slice public APIs (`index.ts`) as conventions.

Shared UI components can be imported directly, for example:

```tsx
import { Button } from "@/shared/ui/button"
```

The shadcn/ui aliases in `components.json` point to `shared` so newly generated primitives follow the same layout.
